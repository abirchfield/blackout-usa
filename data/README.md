# Data

Each subfolder is a **case** - a self-contained power grid. Cases are auto-discovered by `runme.py` and loaded at runtime via the tracked registry at `src/lib/cases/registry.ts`.

```
data/
  runme.py               # prebuild: JSON source -> _out/
  pwdata.py              # PowerWorld -> JSON extraction (offline tool, not used at runtime)
  <case>/
    case.json            # grid metadata and map bounds
    substations.json     # array of substations
    branches.json        # array of transmission lines
    borders.json         # [[lng, lat], ...] polygon ring for region outline
  _out/                  # generated by runme.py (gitignored)
    manifest.json        # ordered case list used by runtime registry
    <case>/lookups.ts    # SUB / LINE ID constants for scenarios
    <case>/grid-data.json # runtime bundle: case metadata + gridData

src/lib/cases/
  registry.ts            # tracked case loader (generated bundle + scenarios)
  scenarios/
    <case>.ts            # gameplay scenarios (briefings, events, weather)
```

## Adding a new case

1. Create `data/<case>/` with `case.json`, `substations.json`, `branches.json`, `borders.json`
2. Create `src/lib/cases/scenarios/<case>.ts`
3. Run `python data/runme.py` then `npm run build`

## JSON formats

### case.json

```json
{
  "name": "Texas",
  "referenceBus": "Bryan",
  "timeConfig": { "startHour": 13 },
  "mapConfig": {
    "bounds": { "xMin": -107, "xMax": -93, "yMin": 25.5, "yMax": 37 }
  }
}
```

| Field | Description |
|---|---|
| `name` | Display name |
| `referenceBus` | Slack/reference bus (substation name) |
| `timeConfig.startHour` | Hour the shift begins (24h) |
| `mapConfig.bounds` | Longitude/latitude bounding box for the map view |

### substations.json

Each substation has `Name`, `Latitude`, `Longitude`, and a `Gens` and/or `Loads` block:

```json
{
  "Name": "Armstrong",
  "Latitude": 27.0,
  "Longitude": -97.6,
  "Gens": {
    "Category": "Wind",
    "Pmax": 108.8, "Pmin": 0, "Ramp": 25, "StartTime": 20,
    "FixedCost": 600, "FuelCost": 0,
    "U": [{ "Status": "IN", "P": 71.0 }, { "Status": "DIS", "P": 0 }]
  }
}
```

- **Gens block**: `Category` is one of: Wind, Solar PV, Gas Turbine, Gas Combined Cycle, Coal-fired Steam, Nuclear Steam
- **Loads block**: same shape but no `Category` (always "Load"). Optional `LoadCategory` (Residential/Commercial/Industrial/Datacenter) as block default or per-unit override.
- Block params (`Pmax`, `Pmin`, `Ramp`, `StartTime`, `FixedCost`, `FuelCost`) are defaults - individual units in `U` can override them.
- Each unit: `{ "Status": "IN"|"DIS", "P": <MW> }`

### branches.json

```json
{ "Number": 1, "FromBus": "Abilene", "ToBus": "McCamey", "Z": 0.2, "Pmax": 500 }
```

`FromBus`/`ToBus` reference substation names. `Z` is impedance, `Pmax` is thermal limit in MW. Numeric IDs and derived fields are computed by `runme.py`.

### borders.json

A single array of `[longitude, latitude]` coordinate pairs forming a closed polygon for the region outline on the map.

## Generated bundle

`_out/<case>/grid-data.json` is the runtime bundle and contains:

- case metadata: `name`, `referenceBus`, `mapConfig`, `timeConfig`
- computed network payload under `gridData`: `subs`, `branches`, `borders`, `nsubs`

`_out/manifest.json` contains ordered case names (for example `{"cases":["texas","hawaii"]}`) and is the source of truth for route/order selection in `src/lib/cases/registry.ts`.

## scenarios

Each case exports `scenarios: Record<number, Scenario>` - one entry per in-game day. Key fields:

| Field | Type | Purpose |
|---|---|---|
| `info` | `string[]` | Briefing bullet points shown at day start |
| `costs` | `{ record, good, okay }` | Cost thresholds ($/MWh) for scoring |
| `weather` | `{ load, sun?, wind? }` | Weather curve presets from `$lib/weather` |
| `hints` | `string[]` | Optional hints shown to the player |
| `start(t, grid)` | function | Runs once at day start - set up initial trips/damage |
| `update(t, grid)` | function | Runs every tick - trigger timed events |

Scenarios reference substations and lines via the auto-generated `SUB` and `LINE` constants from `$data/_out/<case>/lookups` (for example `SUB.Houston`, `LINE.FtWorth_Abilene`).
